HIGH-PERFORMANCE INFRASTRUCTURE

Engineered to Solve Hospital Queue Bottlenecks

Traditional hospital software creates database write-locks every time a waiting room TV updates. SwasthyaQueue separates read-heavy dynamic calculations from durable persistence.

⚡
Redis In-Memory Tier

Sub-Millisecond Dynamic Priority Engine

In busy hospitals, calculating priority scores on the fly can trigger N database writes for every queue refresh. SwasthyaQueue leverages Redis key-value storage with custom serialization to compute and update live queue positions in sub-milliseconds without disk I/O drag.

Spring Data Redis Custom RedisConfig Serializer Zero DB Write Locks
🔗
Clinical DAG Enforcement

Strict Department Prerequisites

Patients cannot jump into specialized consultations without completing required diagnostics. SwasthyaQueue validates that prerequisite department tokens (e.g. Pathology Blood Test) have COMPLETED status before permitting new token generation.

DepartmentPrerequisite Entity Pre-Check Guard
⏱️
Triage Fairness Algorithm

Dynamic Aging & Severity Formula

Triage equation: Score = (Severity × 10) + (WaitingMinutes × 0.3). Critical patients (Severity 4–5) immediately bypass the queue, while patients waiting over 30 minutes steadily gain priority to guarantee anti-starvation.

10x Severity Factor 0.3x Aging Multiplier
🔄
Persistence Layer

Automated Two-Tier PostgreSQL Synchronization

PostgreSQL remains the durable source of truth with database sequences (nextval()) guaranteeing zero token collisions. A background Spring daemon configured with @Scheduled(fixedRate = 30000) periodically flushes recalculated priority scores from Redis back to disk.

Spring @EnableScheduling 30s Periodic Batching PostgreSQL nextval()
